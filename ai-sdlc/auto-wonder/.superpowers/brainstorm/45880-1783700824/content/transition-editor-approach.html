Status Template: Transition Editor UX

How should users define allowed state transitions (from → to)?

Approach A: Table-Based
需求 (REQ) 默认模版
从状态 到状态 名称 操作
newdeveloping开始开发删除
developingverifying提交验证删除
verifyingreleased发布删除
*canceled取消删除

A: Table / List

Simple from→to table. Each row is a transition. Add/delete rows. Fast to build, familiar UX.

Approach B: Visual State Graph
拖拽节点 · 点击连线编辑 · 右键添加

B: Visual Graph (G6/Canvas)

Interactive state machine diagram. Drag nodes, draw arrows to create transitions. Rich but complex to build.

Approach C: Hybrid (Nodes + Table)
状态节点
🟢 new (初始) 🔄 developing 🔄 verifying ✅ released (终态) ❌ canceled (终态) + 添加
流转规则
new → developing 开始开发 ×
developing → verifying 提交验证 ×
verifying → released 发布 ×
+ 添加流转规则

C: Hybrid (Tag Nodes + Inline Transitions)

Nodes as editable tags with category colors. Transitions as compact from→to cards below. Good middle ground — visual enough, no graph library needed.
