# 项目配置备份

在项目侧边栏「配置 → 项目配置备份」中点击「立即备份到云端」。创建、查看历史和下载均要求当前项目 ADMIN 权限。接口只使用登录上下文中的工作空间，不能通过参数指定其他项目。当前实现提供手动导出与下载，不包含自动恢复或定时备份。

## 发布准备

1. 在目标数据库手动执行 `docs/migration/V057__project_backup.sql`；应用不会自动建表。全新数据库的 `docs/autowonder-schema.sql` 已同步包含此表。已有环境应具备当前版本的其他表及迁移（含 V048 执行器配置）。
2. 复用现有 OSS 连接配置。可设置 `oss.backup-bucket` 指定备份 Bucket；未设置时依次使用 `oss.artifact-bucket`、`oss.bucket`，优先复用当前环境的产物 Bucket，避免选中基础配置中不同地域的旧默认 Bucket。Bucket 必须已存在且与 `oss.endpoint`（以及用于签名下载的 `oss.public-endpoint`）地域一致，服务账号须具备该路径的读、写、删除权限。沿用现有 S3 后端的部署也可使用相同备份能力；内存存储会被拒绝，避免重启后备份丢失。
3. 备份对象路径：`project-backups/{workspaceId}/{backupId}.zip`。建议使用私有 Bucket，下载采用有效期 300 秒的签名链接。历史只持久化对象引用，不存储签名 URL。

配置示例（与现有 OSS 配置合并）：

```yaml
oss:
  backup-bucket: your-private-backup-bucket
```

## 备份规则（格式版本 1）

规则集中在 `ProjectBackupRules`，明确指定每张表的列、项目范围和软删除过滤，禁止自动扫描数据库导出。新增配置类型时须显式增加规则、检查敏感字段及关联范围，并更新格式版本/测试/文档。读取配置使用只读 REPEATABLE READ 事务；上传 OSS 在数据库快照事务结束后进行。

| 范围 | 内容 |
| --- | --- |
| 项目与权限 | 项目资料、背景、所有者、成员及访问级别/身份标签；不包含账户密码和登录令牌 |
| SDLC 与状态机 | SDLC、步骤、路由、指令、清单、门禁、状态模板、节点与流转规则 |
| 数字员工 | 员工及配置版本、仓库权限、技能绑定、记忆绑定；不包含版本审核人/意见/审核时间 |
| 小队 | 小队、成员、项目自定义及平台共享的小队模板 |
| 仓库与知识 | 仓库元数据、关系、已沉淀的仓库结论、各范围记忆正文及来源引用；不递归导出来源工单或会话 |
| 技能 | 安装配置、元数据及 OSS 技能包原文件；缺文件或 MD5 不一致时整次备份失败 |
| 执行器 | 员工绑定、名称、客户端类型、启动配置；排除令牌、在线状态、心跳、连接 IP |
| 项目设置 | AI 配额、通知偏好、系统设置；不含 AI 用量和通知消息 |
| 集成 | 外部项目绑定、状态映射、机器人配置；排除同步游标、运行水位、错误及回调密钥 |
| 定时任务 | 指令、调度及关联配置；排除运行记录、上次/下次触发时间。未来恢复时应先禁用任务，再重新计算调度 |

不导出工单、评论、执行/派发、会话及消息、产物、审核记录、自进化提案、审计日志、通知、用量、集成过程记录、权限申请、登录/MCP 令牌。已软删除的配置主体不导出。员工配置的历史版本属于配置，保留用于追溯版本引用。

系统设置中标记为密钥的 `value_json` 导出为 null，保留 `is_secret`、`credential_ref`；其他集成凭据也仅保留引用，不访问密钥中心解密。飞书绑定不导出包含回调验证凭据的凭据包，恢复后需重新填写 App Secret、Verification Token 和 Encrypt Key。迁移环境时需重新绑定凭据、设置机器人回调密钥并重新签发执行器令牌。用户自己写入自由文本、仓库 URL、记忆和技能包中的内容原样保留。仓库源码、头像及其他外部 URL 资源不下载；备份范围是项目配置与已存知识。

## 文件和状态

- `manifest.json`：格式版本、项目 ID、操作者、快照时间、各表行数、排除范围、凭据处理说明、文件 SHA-256、技能包原对象引用与包内路径映射。
- `config/{table}.json`：配置快照。保留原 ID 及关联 ID，跨项目迁移需要映射 ID、用户账号和凭据引用，不能直接按原 ID 插入。
- `packages/skill-{id}.zip`：原始技能包。
- 历史保存备份 ID、项目、操作者、状态、对象引用、大小、整包 SHA-256、时间和失败原因。`RUNNING → SUCCEEDED / FAILED`，仅成功记录允许下载；文件不存在返回明确错误。

当前为同步备份：单表最多 100000 行、未压缩配置与技能包总计最多 64 MiB，超限明确失败。页面请求超时为 5 分钟，网关也需要允许相应请求时长。请求超时后先刷新历史，确认结果后再重试。若进程在备份期间崩溃，记录可能停在 RUNNING，应确认原实例已终止后由运维标记失败再重新备份。备份没有自动删除策略，保留周期由 Bucket 生命周期管理；过期对象的历史记录会保留。

接口：`POST /api/workspaces/current/backups` 创建；`GET` 同路径分页查询（page/size，默认 1/20，size 最大 100）；`GET /api/workspaces/current/backups/{id}/download` 获取临时下载链接。
