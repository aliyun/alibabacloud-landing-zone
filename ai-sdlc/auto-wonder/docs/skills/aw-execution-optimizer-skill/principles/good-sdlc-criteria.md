# 好 SDLC 的三条正面标准

## 1. 硬模板(实证有效)
- 固定小节标题
- 无内容填「无」
- 不得自由发挥

实测效果:输出体量是散文式的 1/4(752 vs 2944 字符),字段完整度 10/10。

## 2. 明确分支判据
- 首次/返工有清晰判据(如"有无前序反馈")
- 每个分支给出具体动作
- 不允许模糊地带

## 3. 环境约束 + 兜底
- 明确"什么不能做"(如"不启动整个 Spring Boot")
- 对客观限制给降级路径(如"标注为不适用,不据此判定失败")
- 不因环境缺失而让步骤卡死

## SDLC 自检清单

对每个步骤问:
- [ ] 每个动作是否有规模约束(budget notes)?
- [ ] 每个度量是否给了工具与口径?
- [ ] 点名的每个工具,执行环境/包内是否真的有?
- [ ] 是否有反事实禁令?
- [ ] 输出要求是否为硬模板?
- [ ] 是否有大段兜平台缺口的降级散文?
- [ ] 是否声明了可复用上游产出?
- [ ] checklist / gatePolicy 是否非空?
- [ ] 有长命令的步骤,是否有一句"当前回合内拿到结果 + 鼓励并行发起 + 不要结束回合去等"?(抄 `detectors/sdlc-bad-patterns.md` 特征 8 的模板;只要这一句,不要展开写回合预算和失败后果,也不要写成"禁止用 `&`"——那会连并发一起禁掉)
