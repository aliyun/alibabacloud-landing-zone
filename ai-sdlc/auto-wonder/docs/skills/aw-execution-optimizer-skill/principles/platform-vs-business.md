# 平台事实 vs 业务指令

## 判据
换一个完全不同行业的客户、换一套完全不同的 SDLC,这个改动是否仍有价值?
- 是 → 平台
- 否 → 业务(SDLC/Agent 定义)

## 平台该做的(声明事实)
- output/ 被封存,workspace/ 不被封存
- 哪些 MCP/skill 可用,哪些不可用
- evidenceRefs 的路径基准是什么
- 步骤边界发生了什么(artifact.sealed 事件)
- 节点间的时间消耗数据透出（可观测性）

## 平台不该做的(业务指令)
- 告诉 agent 把脚本放哪里
- 假设业务有 harness/浏览器验收
- 写死任何工具名/版本/路径
- 规定交付物怎么组织

## SDLC 该做的(业务取值)
- 用什么工具跑测试(如果需要约束)
- 输出模板(如果需要固定格式)
- 规模预算(如果需要约束)
- 复用规则(前步产出是否可引用)

## SDLC 不该做的
- 替平台声明环境(端口/路径/仓库地址 → 由平台 contract 动态注入)
- 替平台兜能力缺口(写降级 URL → 由 Available Capabilities 清单驱动)
