## 问题详情(示例 3 条)

### [SDLC] B1-3: 子代理白派 + 并发争抢
- **步骤:** 400164「需求分析与评论」
- **证据:** 18:27:25 派出 Explore 子代理(6m00.1s);主线立刻做同样的 Read/Grep 25 次;
  子代理返回后主线只说"Great report"然后建分支。WAIT 中位从 3.43s 抬到 9.72s(同步骤内)。
- **影响:** 子代理耗时 + 并发争抢 ≈ 4m50s 纯浪费
- **建议:**
  - Agent.md Scale 加: "不派子代理做调研;若需搜索用 Grep/Glob 即可,禁止 Agent 工具"
  - SDLC instructionMd 末尾加: "【预算约束】不派子代理;只读与本次改动直接相关的文件"
- **预期信号:** 重跑后 400164 不出现 `tool=Agent` 事件

### [SDLC] B2-1: 反事实禁令
- **步骤:** 400175「条件部署」
- **证据:** 指令含「不能直接判断缺少部署能力」;agent 做了 24 个探测动作(which/npm view/
  npm search × 8 条路径),最终自己写了一份能力缺失记忆。基线 6 动作 → 验证轮 24 动作。
- **影响:** +1m59.1s
- **建议:**
  - 删除「未查询到已有变更时应继续创建,不能直接判断缺少部署能力」
  - 改为: "查看平台 Available Capabilities 清单:若 aone-mix 可用则使用;不在清单中则直接
    记录'部署能力暂不可用',不要探测不要安装"
- **预期信号:** 400175 动作数 ≤ 3
