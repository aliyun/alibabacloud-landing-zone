# 工单 SDLC 阶段耗时

工单的交付进度卡片展示当前执行的阶段耗时图。点击「SDLC 阶段耗时」可在工作台查看，使用已有执行选择器切换历史执行。各步骤显示耗时、占比、状态，并突出耗时最长的步骤；支持按流程或耗时排序。

## 统计口径

- 以单个 dispatch 为边界，不合并其他重试、员工或交互会话。
- 复用步骤事件的区间计算：从 `step.started` 到步骤完成、失败、复用或失效事件；同一步骤多次执行累加区间，不计算区间之间的间隔。
- 运行中的开放区间计算到本次查询；已结束或暂停的执行以其最后更新时间封顶。缺少执行结束时间时使用最后已记录事件时间。
- 时间包含模型响应、工具调用、校验及步骤内等待，不代表模型的纯推理时间。
- 占比的分母是所选执行已记录的步骤耗时之和。执行启动前、步骤外的间隔不会被摊入步骤，因此累计步骤耗时不一定等于执行总耗时。
- 没有开始事件的步骤保留空耗时，显示「—」，不把缺失数据当作 0 秒。未执行步骤、复用或跳过的步骤仍可在列表中看到。
- 历史流程通过该 dispatch 的入口步骤解析，避免沿用员工后来绑定的新 SDLC；已记录的步骤名称优先保留。入口步骤定义已删除或不可用时显示无数据，不推测流程。

## 接口

现有工单 `delivery-progress` 响应的 `executions[]` 增加可选 `stepTimings[]`，包含 `stepId`、`name`、`status`、`durationMs`。沿用已有进度轮询，无需额外拉取完整运行日志，也没有数据库结构变更。
