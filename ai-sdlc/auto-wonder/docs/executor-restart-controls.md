# 执行器启动时间与远程重启

部署前执行 `docs/migration/V061__executor_last_started_at.sql`。`lastStartedAt` 来自 runtime 进程启动时固定的 UTC 时间，断线重连不会变成新的启动；旧客户端返回空值，界面显示“未上报”，离线后保留最近启动时间。

执行器列表压缩为名称、归属、客户端版本、状态、最近启动和操作。详情抽屉承载 IP、心跳、创建时间、凭据与客户端维护操作；Token 只在管理员主动查看时读取，关闭详情后从页面状态移除。

管理员使用 `POST /api/executors/{id}/restart`，请求体 `{ "update": false }` 重启当前程序；`update: true` 检查并应用最新发布版后重启。必须在当前空间、在线、已上报启动时间且声明对应协议能力。请求通过已有 WebSocket / 跨节点 mailbox 下发，不接受路径、命令或下载地址。

请求有唯一 ID，平台阻止重复点击；客户端拒绝过期、错误 executorId 和重复 ID。任务或会话忙碌时返回失败，空闲再操作，不强制取消任务。页面区分 REQUESTED、UPDATING、RESTARTING、COMPLETED、FAILED、TIMED_OUT。只有关联请求 ID 且启动时间更新的新心跳才确认重启成功；发送命令成功不代表客户端已重启。结果保留 24 小时，10 分钟没有确认显示超时。

兼容性：
- macOS/Linux 新版客户端支持重启当前程序。
- 标准安装的稳定发布版支持更新并重启，复用下载验证、空闲检查、原子替换和失败回滚。
- 本地 dev/源码版不会下载发布版覆盖本地程序；先在本地编译，平台可重启已编译程序。
- Windows 当前不声明远程重启能力（现有自动更新安装器同样不支持 Windows）；界面禁用相应操作。
- 旧客户端需要先本地升级一次。

## 编辑并在线应用完整启动命令

启动命令弹窗中的“编辑完整命令”读取平台当前保存的 POSIX 命令，不会因为进入编辑而保存表单。管理员可以修改 `autowonder@X.Y.Z`、`--workspace-root`、`--name`、`--debug` 以及已有的模型、推理强度、上下文、记忆模式和最大并发参数。

点击“保存命令”成功后返回外层参数页，同步参数并刷新命令预览。“在线应用（重启）”位于外层“复制 debug 模式命令”右侧，先选择“空闲时重启”或“强制重启”，再保存当前参数并按返回的配置版本下发；等待响应、重启完成或失败状态也在外层展示。仅保存命令不会触发重启。选择 Windows 命令格式时，“在线应用（重启）”禁用并说明仅支持 macOS / Linux；仍可保存或复制命令，在本机手动启动。切回 macOS / Linux 后，仍需满足在线状态和客户端能力等条件。

外层修改模型、推理强度、上下文、记忆模式和并发数时，通过只读预览接口即时更新命令，并标记“未保存”。预览复用保存时的参数校验和命令转义，不写入配置或下发执行器；取消会丢弃草稿。切换模型保留当前支持的推理强度和上下文窗口，仅对缺失或不支持的值补默认值；新建执行器和启动配置弹窗使用同一规则。进入“编辑完整命令”时保留当前表单草稿，复制、保存配置和在线应用仍先保存正式配置。

`PUT /api/executors/{id}/launch-command` 接收 `{command, version}`，校验命令后将参数写回现有 `launch_config` JSON，并返回更新后的乐观锁版本。版本、目录、进程名称和 debug 扩展项会被旧表单写入保留；MCP 查询和各 OS 的命令生成使用同一份保存值。原始命令及其明文 Token 不持久化。只接受 `npx -y autowonder@固定版本 connect` 的受支持参数；连接地址、Token、执行器 ID、provider 和 Token 代理参数不可修改，拒绝重复参数、Shell 扩展、管道与重定向。

`POST /api/executors/{id}/launch-command/apply` 只接收保存后的 `{version}`，拒绝过期版本，并通过现有重启通道下发结构化启动参数。客户端必须声明 `EXECUTOR_LAUNCH_COMMAND_V1`。平台只在收到关联请求 ID、更新的启动时间和准确目标版本的新心跳后标记完成；保存、投递和完成是不同阶段。

同版本直接按新环境参数 exec；更高稳定版本复用精确 npm 版本解析、完整性检查、候选自检、原子替换和失败回滚。版本切换仅支持标准路径安装的稳定发布版，不支持在线降级。本地源码版可在不切换版本时应用参数。该能力独立于后台自动更新开关，不会开启 npm latest 轮询。命令里显式固定的版本不会被服务端自动升级覆盖，手动版本升级仍是独立的操作。

变更工作目录前检查空闲、待确认结果及默认本地队列中的待执行任务，检查目标目录可写；原目录和历史任务文件不迁移、不删除。没有指定目录或进程名称时在线应用沿用当前值，仅更新其他参数不会移动本地队列。工作目录切换后，原目录中的历史本地任务文件仍需从原目录访问。Windows 和旧客户端可保存命令并手工启动，尚不能在线应用。

验证入口：后端启动配置、命令解析、重启与升级测试；前端执行器页面测试和生产构建；Runtime daemon/updater/config/workgate 测试。标准 E2E 的 `executors.configuration-and-query` 覆盖完整命令保存、版本冲突与 Shell 拒绝，`executor.launch-command` 使用当前 Linux 源码产物验证同版本参数应用、关联心跳和目录切换。公网 npm 跨版本切换需对发布候选单独验收。

## 在线应用的失败条件

- 保存前：无管理员权限、参数不完整或不合法、模型已下线、配置被其他操作修改，会阻止保存和下发。
- 下发前：执行器离线、不支持在线应用、尚未上报启动时间，或已有重启请求，服务端拒绝；传输异常显示发送失败。
- 客户端处理：请求超过一分钟或时钟偏差过大、运行中的任务/会话占用工作门、已有更新操作，都会拒绝本次重启，不自动排队等待。
- 切换目录：仍有等待服务端确认的结果、默认本地队列仍有任务、无法读取队列/结果，或目标目录不能创建/写入，会拒绝切换；这些限制保护原目录任务和未确认结果。
- 切换版本：不支持降级；本地源码/dev 或非标准安装不能在线切换版本。目标版本不可用、已安装二进制与指定版本不一致、网络下载、完整性/自检、文件替换或进程重启失败，也会使在线应用失败。同版本应用参数不要求下载新包。
- 完成确认：只有收到关联请求 ID、更新的启动时间以及正确目标版本的新心跳才算成功；十分钟未满足会显示超时。下发成功不等于重启成功。

在线应用会先保存配置。保存成功后再发生下发、客户端执行失败或超时，已保存的配置会保留；可以排除原因后重试，或复制命令在本机启动。

## 在线应用的重启方式

新版 macOS/Linux Runtime 心跳声明 `EXECUTOR_RESTART_POLICY_V1`，列表返回 `restartPolicySupported`。在线应用请求 `{version, restartMode}` 接受 `WHEN_IDLE` 和 `FORCE`；服务端只下发已保存的结构化参数，未知值或不具备新能力的客户端会被拒绝。旧调用省略 `restartMode` 时保留原有“忙碌即失败”的行为；详情中的普通远程重启不变。应先发布 Runtime，再部署服务端和前端；旧客户端可保存、复制命令，并在本机升级后使用新选项。

- **空闲时重启**：关闭新任务和对话入口，保持当前执行继续，等待任务、对话及恢复工作结束后重启。客户端报告 `WAITING_IDLE`，每 30 秒续报进度并续期请求锁；等待本身没有十分钟总上限。连接断开会取消本次等待并重新开放入口；平台连续十分钟未收到进度显示超时。进入重启阶段后重新计算十分钟确认期限，只有新的关联启动心跳确认完成。
- **强制重启**：允许中断当前任务和对话，原地重执行进程，沿用既有本地恢复、服务端领取和旧进程回收流程。不会把任务标记为主动取消或暂停。进度只能从已有恢复材料或最近可用 checkpoint 恢复，可能重新准备或重复部分工作，对话不保证恢复；不能宣称无损或外部副作用只发生一次。

两种方式都不能抢占其他更新/GC 的维护锁，仍检查稳定版本、下载完整性、原子安装和失败回滚。强制模式保留结果 outbox 可读性检查；有活动工作或尚在恢复扫描时不能切换工作目录，待确认结果和旧默认队列也仍阻止目录切换。重启失败会还原环境并重新开放入口。Windows 不声明新能力，前端选择 Windows 格式时禁用在线应用。
