# 执行器启动时间与远程重启

部署前执行 `docs/migration/V061__executor_last_started_at.sql`。`lastStartedAt` 来自 runtime 进程启动时固定的 UTC 时间，断线重连不会变成新的启动；旧客户端返回空值，界面显示“未上报”，离线后保留最近启动时间。

执行器列表压缩为名称、归属、客户端版本、状态、最近启动和操作。详情抽屉承载 IP、心跳、创建时间、凭据与客户端维护操作；Token 只在管理员主动查看时读取，关闭详情后从页面状态移除。

管理员使用 `POST /api/executors/{id}/restart`，请求体 `{ "update": false }` 重启当前程序；`update: true` 检查并应用最新发布版后重启。必须在当前空间、在线、已上报启动时间且声明对应协议能力。请求通过已有 WebSocket / 跨节点 mailbox 下发，不接受路径、命令或下载地址。

请求有唯一 ID，平台阻止重复点击；客户端拒绝过期、错误 executorId 和重复 ID。任务或会话忙碌时返回失败，空闲再操作，不强制取消任务。页面区分 REQUESTED、UPDATING、RESTARTING、COMPLETED、FAILED、TIMED_OUT。只有关联请求 ID 且启动时间更新的新心跳才确认重启成功；发送命令成功不代表客户端已重启。结果保留 24 小时，10 分钟没有确认显示超时。

兼容性：
- macOS/Linux 新版客户端支持重启当前程序。
- 标准安装的稳定发布版支持更新并重启，复用下载验证、空闲检查、原子替换和失败回滚。
- 本地 dev/源码版不会下载发布版覆盖本地程序；先在本地编译，平台可重启已编译程序。
- Windows 当前不声明远程重启能力（现有自动更新安装器同样不支持 Windows）；界面禁用相应操作。
- 旧客户端需要先本地升级一次。

验证：后端相关单元/路由测试、前端执行器页面测试和生产构建。没有执行真实发布版更新。标准内部 E2E 在 PREFLIGHT 因 Docker Desktop 安装需要管理员密码退出，平台未启动；当前宿主机不支持安装 Docker，后续不再尝试。标准 stop/clean-up 因缺少 docker 命令未完成，但预检未创建容器、网络或数据库；失败诊断保留在标准脚本的临时运行目录。
