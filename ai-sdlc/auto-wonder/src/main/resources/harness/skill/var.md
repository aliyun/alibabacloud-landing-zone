## 初始化前一次性收集与实例化

先读取模板 variables 声明与占位符位置，建立 token→含义→所需信息→填写状态清单。客户端选择卡提交后，按下方「客户填写模板」输出：填写说明放在代码块外，五部分客户填写内容及全部示例必须完整保留在同一个独立的 text 围栏代码块内，客户使用代码块的复制按钮一键复制。不得去掉代码围栏改为普通 Markdown 展示，不拆成多个代码块，不用整条消息复制代替模板复制。保留五部分结构、全部填写示例及示例标记，不改写为只有字段名和空白值的表单。已知项用客户已确认的实际信息预填并标明已提供，未知项保留具体示例供替换；进度说明、填写提示和后续步骤必须放在代码块外。不把内部变量映射表或 Chief 内部处理规则放进代码块，不将部署扩展为复杂表格或多轮问卷。示例不是默认配置，不代表客户已提供信息，未获客户明确反馈不得将其用于预检或初始化。

### 客户填写模板

请复制下面的模板，将示例替换为实际项目信息。支持多个仓库；不适用的内容写“不适用”，暂不清楚的写“待确认”。**不要在聊天中填写密码、Token 等敏感值。**

```text
#### 1. 代码仓库

填写仓库英文名称、地址、默认分支、描述及仓库关系。

**示例：**

- `console`：`git@CUSTOMER_REPOSITORY_HOST:CUSTOMER_REPOSITORY_PATH/console.git`；默认分支 `CUSTOMER_DEFAULT_BRANCH`；系统前端，React。
- `server`：`git@CUSTOMER_REPOSITORY_HOST:CUSTOMER_REPOSITORY_PATH/server.git`；默认分支 `CUSTOMER_DEFAULT_BRANCH`；系统服务端，Java。
- 仓库关系：`console` 是 `server` 的前端，通过 API 调用服务端。

#### 2. 构建与测试

按仓库填写执行目录、构建命令和单元／组件测试命令。以下命令仅为示例，请填写项目实际可执行的命令。

**示例：**

- `console`：在仓库根目录执行；构建 `npm ci && npm run build`；测试 `npm run test -- --run`。
- `server`：在仓库根目录执行；构建 `./mvnw -B -DskipTests package`；测试 `./mvnw -B test`。

没有测试命令请写“尚未配置”。覆盖率沿用模板固定配置，无需填写。

#### 3. 数据库脚本

涉及数据库脚本变更时，说明脚本位置、结构维护方式、执行方式及备份恢复约定。

**示例：**

> 脚本位于 `server` 仓库的 `sql/migrations/`，按 `V日期_序号__说明.sql` 命名；最新完整表结构维护在 `sql/schema.sql`。由部署脚本统一执行迁移，执行前备份，执行后核对迁移版本和结果；失败后停止部署，经确认使用备份恢复。

仅连接数据库、不执行脚本变更时，填写“仅连接数据库，本节不适用”；不使用数据库时，本节和下一节均填写“不适用”。

#### 4. 数据库配置

填写数据库类型、版本和连接配置的读取方式，**只提供配置项名称，不提供实际连接值**。

**环境变量示例：**

> `server` 使用 MySQL 8.0，通过环境变量 `DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USERNAME`、`DB_PASSWORD` 读取连接配置。

**配置文件示例：**

> `server` 使用 MySQL 8.0，读取 `config/application-test.yml` 中的 `spring.datasource.url`、`spring.datasource.username`、`spring.datasource.password`。

**推荐在 AutoWonder 平台统一配置环境变量及敏感值，无需到执行器所在环境逐个手动配置。**

#### 5. 部署

说明**每个仓库的部署目标分支**，以及部署脚本或 Skill 和参数。

部署前，将本工单已通过评审和测试的开发分支合并到对应部署分支并推送，**使用合并后的部署分支版本进行部署**。各仓库的部署分支可以不同，也不必与仓库默认分支一致。

**工程脚本示例：**

> 将本工单 `console` 仓库的开发分支合并到 `CUSTOMER_CONSOLE_DEPLOY_BRANCH`，将 `server` 仓库的开发分支合并到 `CUSTOMER_SERVER_DEPLOY_BRANCH`，分别推送到远程。部署时，各仓库切换并同步对应部署分支，在工程根目录执行客户提供的 `CUSTOMER_DEPLOY_SCRIPT`，完成授权测试环境部署。

**部署 Skill 示例：**

> 将本工单 `console` 仓库的开发分支合并到 `CUSTOMER_CONSOLE_DEPLOY_BRANCH`，将 `server` 仓库的开发分支合并到 `CUSTOMER_SERVER_DEPLOY_BRANCH`，分别推送到远程。随后调用 `CUSTOMER_DEPLOY_SKILL` Skill，参数示例为 `ProjectID: CUSTOMER_PROJECT_ID`、`JobID: CUSTOMER_JOB_ID`。客户须确认实际 Skill 的参数契约及任务配置，分别部署 `console` 的 `CUSTOMER_CONSOLE_DEPLOY_BRANCH` 分支和 `server` 的 `CUSTOMER_SERVER_DEPLOY_BRANCH` 分支。

使用 CI/CD 平台时，请先将其 API 封装为 Skill，上传到 AutoWonder 并完成必要的审核发布；已有已发布的 Skill 可直接复用。空间初始化会统一完成与部署数字人的绑定及必要发布，无需再单独绑定。**Skill 名称、参数及任务分支配置均以实际配置为准。**
```

### Chief 内部处理规则（不包含在客户填写模板中）

不索取密码原文。未知变量交由流程维护者处理，不临时新增客户问题。不得询问项目形态、MR/PR、覆盖率或独立冒烟信息。MR/PR 固定为不创建 MR/PR、保留内部代码评审；覆盖率沿用模板 Skill config；只读冒烟固定不适用。仓库数量在实际绑定后判断。

1. 收到反馈后核实所需信息，不适用必须有条件和依据；未回答或缺配置不能视为不适用。已知信息直接复用，只补同一清单的必要缺项。
2. 将声明中的每一个完整 token 映射到最终配置字符串，组成 `variableValues`；同步整理仓库、依赖关系、逐角色仓库权限及已发布部署 Skill 绑定，组成 `configurationChanges`。将两者一并提交给 `autowonder.preview_workspace_initialization`。值不得含未解析占位符，不得省略固定值或不适用项，不得把填写示例当成已确认配置。
3. 统一预检冻结全部值、模板版本、默认执行器及仓库/权限/部署绑定。缺失值、未知变量或冲突阻止初始化。信息完整且预检无冲突后，先展示简洁方案及工具执行后的后续指引，再直接执行 `autowonder.initialize_workspace`，不追加确认题、JSON 计划或单独配置应用。
4. 服务端在创建实例前完成替换，首次创建的 SDLC 即包含最终配置。母版与 variables 声明保留；登记声明本身不算残留。初始化后不得再进行一轮相同变量收集或替换。
5. 保存已应用值及变量所在实例步骤，后续客户主动修订按精确差异应用，不重新套用母版覆盖其他修改。失败恢复使用原冻结值，不换模板或信息。
6. 通过 `autowonder.get_workspace_initialization` 查询原统一批次；只有 `status=SUCCEEDED` 才表示模板、变量、默认执行器、仓库/权限/部署绑定及必要发布均已完成，此时为 `RUNTIME_PENDING`，不得等同于执行器在线或 READY。按 SKILL.md 的后续流程读取并提供全部默认执行器的真实启动命令和本地统一管理提示词，客户启动后继续就绪检查。失败或未知先查询原批次，使用 `autowonder.resume_workspace_initialization` 仅补未完成项，不重复初始化。旧分段工具仅用于既有历史批次恢复，不用于新初始化。

## 部署 Skill 接入

只向客户收集一段部署说明：逐仓库部署分支、工程脚本或 Skill 名称及必要参数。读取实际工程脚本或已上传 Skill 核实入口、参数、构建分工、查询与超时策略、成功判定，不要求客户重复填写实现中已经明确的细节。不自行编造未提供的配置；确有阻塞时只补同一部署说明的必要缺项。工程脚本方式不强制封装 Skill；CI/CD API 方式须先提供已上传并完成必要审核发布的 Skill，已有 Skill 优先复用；绑定到测试与部署工程师及绑定的必要发布由统一初始化批次完成。Skill 内部变量与模板变量统一处理，保留作用域避免同名混淆。

将具体调用和配置冻结到统一预检，由统一初始化批次写入本实例对应部署SDLC步骤，以Skill描述的真实入口显式调用，并完成QA绑定及必要发布，不拆成初始化后的独立操作。客户共享Skill需实例参数化或创建专用副本，不直接改写影响其他小队的共享包。Skill负责合并/构建时与原流程职责去重，保留原有门禁和无需部署分支。上传缺失或参数未完成时显示待完成项，不能写入虚构Skill引用。
